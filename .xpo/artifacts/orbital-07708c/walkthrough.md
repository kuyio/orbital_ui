# Walkthrough: dependency update and new baseline

## What was built and why

This moves the repo to a new baseline and refreshes its dependencies:

| Item | Before | After |
|---|---|---|
| `required_ruby_version` | `>= 3.0.0` | `>= 3.4.8` |
| `demo/.ruby-version` | 3.4.8 | 4.0.9 |
| `demo/Dockerfile` `RUBY_VERSION` | 3.4.7 | 4.0.9 |
| Rails | 8.1.1 | 8.1.4.1 |
| `orb_template` | 0.2.5 | 0.3.0 |
| Lucide | 1.27.0 | 1.68.0 |

`orb_template` was the trigger. The `~> 0.2.5` pin in `orbital/orbital.gemspec` excluded 0.3.0, and 0.3.0 requires Ruby 3.4 or newer, so the pin and the Ruby floor had to change together.

## How the pieces fit together

**Two Rubies on purpose.** The gemspec floor (3.4.8) is what library consumers need. `.ruby-version` (4.0.9) is what development and the demo run. Verify both: `orbital/` has no `.ruby-version`, so select the version with `RBENV_VERSION`.

**Gems: minor and patch only.** Both lockfiles were updated with `bundle update --minor`. The held-back majors are listed in orbital-c8c570.

**npm: two steps, and the second matters.** `bun update` moves only direct dependencies. Indirect packages keep their locked versions, which left known-vulnerable `picomatch`, `yaml`, `browserslist` and `immutable` in place. Both `bun.lock` files were therefore deleted and regenerated. Remember this next time: after `bun update`, `bun outdated` can look clean while the lockfile still holds vulnerable indirect versions.

**Icons.** `orbital/lib/orbital/icons.rb` is generated by `bin/generate-icons`. 306 icons were added and none removed, so no references needed changing.

## Decisions worth knowing

- **Lint offences were fixed in code, not config.** The RuboCop bump enabled new cops and added 8 offences. In `text.rb` the constants moved above `private`, and in `progress_bar.rb` the nested min/max became `clamp`. The rest were autocorrected, including `<<~'ORB'` to `<<~ORB` in `modal.rb` and `modal_frame.rb`. That last change is only safe because those templates contain nothing a double-quoted heredoc would interpolate. The cop checks this, but a future `#{` in those templates would now be interpolated by Ruby.
- **The generator was fixed, not its output (orbital-fd975f).** `make test` was already failing on `main` because of 2 offences in `icons.rb`. Autocorrecting the file would not survive regeneration, so `bin/generate-icons` changed instead.
- **Compiled assets are now production builds.** The tracked `orbital/app/assets` bundles were unminified watch output. `make build` replaces them with minified files, which accounts for most of this change's deletions. Note that `orbital/Procfile.dev` runs `parcel watch`, so running it can reintroduce unminified bundles into the tracked files.

## Non-obvious side effects

- **Indirect majors moved in `orbital/bun.lock`:** `@types/node` 24 → 26, `chokidar` 4 → 5, `readdirp` 4 → 5, `undici-types` 7 → 8, and top-level `picomatch` 2 → 4. The minor-and-patch limit applied to what we chose directly; parent ranges allowed these.
- **`index.css` shrank** from 77.31 kB to 71.65 kB between the old and new lockfiles. A rule-by-rule comparison showed no `Orbital-*` selectors lost. The optimizer merges more rules, and browser targets moved to current versions, so older browsers such as Chrome 112 no longer get CSS fallbacks.

## How it was verified

- `make build` and `make test` pass on 4.0.9. `orbital/` RSpec passes on 3.4.8 (20 examples).
- Trivy with dev dependencies and `bun audit` are clean in both projects, apart from one LOW finding (`DS-0026`, no Dockerfile `HEALTHCHECK`). `bundle-audit` and Brakeman are clean on `demo/`.
- All 37 demo pages return 200. Compared with `main` on the old stack, before the lockfile regeneration, rendered HTML differed only in per-request tokens, random IDs and Lucide icon shapes, so `orb_template` 0.3.0 changed no escaping.
- The user clicked through the demo on the final build and confirmed everything works.

## Known gaps

- `demo/` has no tests, so `bin/rails test` passing proves nothing about it.
- The Docker image was not built, so the `ruby:4.0.9-slim` tag and native gem builds in it are untested.
- Trivy skips dev dependencies by default and misses nested `bun.lock` entries, and Brakeman appears to skip `.orb` views. orbital-8aec06 covers these.
